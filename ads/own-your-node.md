# Ad concept — Own Your Node

- **Phase:** Phase 2 — Viral node expansion
- **Objective / goal:** `run_hanzod` node-activation, feeding `signup` and `activate`
- **Audience:** Warm — developers on the waitlist, and cold lookalikes of active node runners
- **Channel(s):** Meta (developer interest + lookalike), YouTube demand-gen, Reddit/HN-style native where allowed
- **Landing page:** `hanzo.ai` node download + "how running a node earns access"

## The idea

Most platforms make you wait for access. Hanzo lets you *earn* it: run `hanzod`
and you become part of the infrastructure — you move up the access queue and earn
points at the same time. Aimed at the developer who would rather do something than
sit on a list.

## Hooks (headlines to test)

1. Skip the line — run a node.
2. Don't wait for access. Become the infrastructure.
3. Your machine, on the network. Access, earned.

## Primary text / script

You're on the waitlist. Here's the fast lane: download `hanzod`, run one command,
and your node starts contributing to the network. Running a node earns the most
points of any action — and points move you up the access queue. You're not
waiting for capacity; you're adding it.

## Call to action

Run a node → (matches the landing page's primary CTA)

## Claims (mandatory — honesty rule)

| Claim in the ad | Status | Source / assumption |
|---|---|---|
| Running `hanzod` earns 25 points | product-fact | Points ledger, `GTM.md` (25 pts / qualifying node) |
| It is the highest-point action | product-fact | Ledger: node 25 > social-follow 15 > referral 10 > share 2 (`GTM.md`) |
| Points move you up the access queue | product-fact | Waitlist mechanics, `GTM.md` |
| One-command install | product-fact | `amplify-node-running` done-criterion, `checklist.yaml` |
| Node points require sustained uptime | product-fact (disclosed) | Abuse guard, `discounts.md` |

## Visual direction

A single terminal command resolving into a live node indicator, then a queue
position ticking upward. Clean, developer-native, no stock-photo people. Produce
in Studio.

## Do-not-say

- No earnings/money claims — node running earns **access and points**, not cash.
  (Compute-share revenue is a separate Phase 3 program with its own brief.)
- No node-performance or throughput numbers until measured in `analysis/`.
